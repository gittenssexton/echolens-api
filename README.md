# EchoLens API

Reproducible stellar observations for investigating electromagnetic outliers.
No anomaly or technosignature scores are generated by this registry.

```bash
pip install -r requirements-dev.txt
python -m scripts.import_gaia          # offline rebuild of frozen 10,000-star snapshot
python -m pytest -q
uvicorn app.main:app --host 0.0.0.0 --port 10000
```

Existing `/` and `/health` responses are preserved. `/docs` documents:

* `GET /stars`: exact source_id, G magnitude, BP-RP, parallax and RA/Dec ranges;
  bounded pagination with total count and deterministic source-ID ordering.
* `GET /stars/{source_id}`: all catalog values, uncertainties, correlations,
  field metadata, provenance, separate catalog inferences and interpretations.
* `GET /catalogs`: import manifest and complete source-column metadata.
* `GET /stars/stats`: loaded registry counts and catalog/import identifiers.
  An unavailable registry returns 503, rather than a scientifically misleading zero count.

Source IDs are strings. Query nulls are excluded by numeric filters. Coordinates
are ICRS degrees; parallax is mas. RA ranges do not wrap: split across zero into
two searches. No angular cone search is claimed. `ECHOLENS_DB_PATH` can select
an independently built database; absent registry returns 503 without changing health.

Explicit refresh (network access; replaces artifacts only after validation):

```bash
python -m scripts.import_gaia --fetch --provider irsa --count 10000
```

If the connection is interrupted, resume the printed job URL with `--resume-job`
(and the same `--format`). Both `votable` and `votable_plain` archive formats are
supported. `python -m scripts.spotcheck_gaia` replays a separate five-source
archive comparison offline; add `--fetch` only for an explicit new network check.

Importer validates TAP status, exact row count, source identity/uniqueness, selection,
coordinates, ordering, finite values, nonnegative uncertainties, correlation bounds,
raw checksum and SQLite integrity; failure leaves the existing database intact.
The frozen sample uses native FITS from NASA/IPAC IRSA’s Gaia DR3 mirror; a
paired VOTable preserves field descriptions, units, UCDs and display formats.
FITS values retain native precision; formatted XML display precision is not
applied to measurements. The ESA provider supports asynchronous VOTable jobs.
Original artifacts and serving-archive provenance are retained. Offline replay is the
reproducibility guarantee; a later live query may reflect archive changes.

The manual **Frozen registry artifact** workflow rebuilds the committed snapshot
offline and exports validated observations, metadata and SQLite as a 30-day artifact.
Artifacts require durable archival; they are not a deployment mechanism.
See [PR reconciliation](docs/PR_RECONCILIATION.md) before combining parallel branches.

## Sample diagnostics

After rebuilding the registry, install `requirements-analysis.txt` and run
`python -m scripts.sample_diagnostics`. This generates `reports/sample_diagnostics.json`
and a sky-coverage and measurement-quality figure. Distribution counts explicitly
include missing values and values outside displayed ranges. These describe sample
and reference-selection biases; they are not anomaly scores. No distance is inferred
by inverting noisy parallaxes. The analysis dependency is separate from API dependencies.

## Deployment safety

Work is proposed on `feat/stellar-registry-gaia-dr3`; do not merge or deploy until
review. Render's start command is unchanged. No Gaia download happens at startup
or inside an API request. For a later reviewed deployment, build the database in
Render's build phase with `python -m scripts.import_gaia` after installing requirements,
or provision the database at ECHOLENS_DB_PATH. Without that step only registry
endpoints return 503; existing health remains operational. Do not refresh a live
SQLite database while requests are running. No Render settings were changed.
